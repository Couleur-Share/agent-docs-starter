本页是本站写法的唯一来源。仓库根目录的 `AGENTS.md` 只摘录其中不可协商的几条，并指向这里。

## 唯一维护位置

每类事实只在一个地方维护，其他页面链接过去，不抄写。派生后把下表换成你自己的分类。

| 资料 | 维护位置 |
| --- | --- |
| 本站的写法与约定 | 本页 |
| AI 查阅方式与 Skill 安装 | [AI 查阅入口](/guide/for-agents/) |
| 已废弃的做法 | `archive/` 下的页面，状态标为 `historical` 或 `superseded` |
| 不属于本站的资料 | 留在原来的地方（项目仓库、收藏工具、密码管理器），本站只放链接 |

判断标准：内容是否属于本站范围，并且需要被反复查阅和遵守。临时笔记、收藏的外部文章和源文件本身都不进本站。

## 页面头字段

| 字段 | 必填 | 写法 |
| --- | --- | --- |
| `title` | 是 | 页面标题；正文不再写一级标题 |
| `description` | 是 | 用一句完整的话说明本页回答什么问题，AI 先靠它决定要不要读全文 |
| `aliases` | 否 | 别名、旧称、英文名，`find` 会一起匹配 |
| `status` | 否 | `current`（缺省，现行）、`historical`（只当历史）或 `superseded`（已被取代） |
| `supersededBy` | 状态为 `superseded` 时必填 | 取代它的页面路由，例如 `/guide/maintenance/`；目标必须是现行页面 |
| `reviewed` | 否 | 最后一次核实内容的日期，写成 `YYYY-MM-DD`；编辑不等于核实，没核实就不改它 |

Nimbus 自带的字段（`sidebar`、`draft` 等）照常可用，见 [Nimbus 文档](https://nimbus-docs.com/)。

## 写作规则

- 页面默认用 `.md`，只有要用组件时才用 `.mdx`：MDX 会把正文里裸写的 `{`、`<` 当成代码，构建会失败。
- 正文只写现状。情况变了就改正文，不在末尾追加流水账。
- 单行不超过 500 字。搜索工具会截断长行，行尾的内容容易被 AI 漏读。
- 易变的数值写上日期，例如“截至 2026-11-07 共有 12 套模板”。
- 截图和示意图旁边用文字写清关键数值和用途，AI 靠文字检索。
- 不写密钥、口令、Token 和授权码，只写它们存放在哪里。
- 新增分区就新建目录，并放一个 `index.md` 作为分区首页，在其中用 `sidebar.group.label` 写分区名。

## 历史记录

被取代的做法有两种处理方式：

- **页内历史**：放在页尾，用 `<div data-history>` 包住若干 `<details>`。查询脚本默认跳过这一块，AI 只在追溯来龙去脉时才读。
- **整页取代**：把旧页面移到 `archive/`，状态改为 `superseded` 并填写 `supersededBy`。

页内历史的写法：

```html
## 变更记录

<div data-history>
<details>
<summary>2026-11-07：改用新的命名规则</summary>

当时的做法和改动原因。

</details>
</div>
```

## 写回流程

1. 用 `find` 找到这件事唯一的维护页面。已有页面就改它，不另起重复页面。
2. 把正文改成现状，旧内容按上一节处理。
3. 内容核实过就更新 `reviewed`。
4. 运行 `npm test`，有错误就修到通过。
5. 只暂存本次改动的文件并提交。
