# {{NAME}}写回

仓库：`{{REPO_DIR}}`，页面源文件在 `{{DOCS_DIR}}`。写作约定以仓库根目录的 `AGENTS.md` 为准，本 Skill 只给流程。

## 什么时候写

- 本次任务定下或改变了{{SCOPE}}中的内容。
- 用户要求更新这份文档。
- 发现文档与实际不一致，并且已经确认了实际情况。

纯查询、没有产生新事实时不写。

## 步骤

1. 用 `{{QUERY}} find <关键词>` 找到这件事唯一的维护页面。已有页面就改它，不另起重复页面；拿不准归属时先问用户。
2. 正文只写现状：直接改正文，不在末尾追加流水账。被取代的旧做法移进页尾的 `<div data-history>` 折叠区，或者整页标为 `status: superseded` 并填写 `supersededBy`。
3. 新页面必须有 `title` 和一句完整的 `description`，需要时补 `aliases`。内容核实过才更新 `reviewed`（YYYY-MM-DD）。
4. 运行 `{{CHECK}}`，有错误就修到通过。
5. 在仓库里只暂存本次改动的文件（`git add -- <文件>`）并提交，提交信息写清改了什么。是否推送按 `AGENTS.md` 的约定；没有约定时先问用户。

## 边界

- 不写密钥、口令、Token、授权码或私人联系方式，只写它们存放在哪里。
- 不顺手改与本次事实无关的页面。
